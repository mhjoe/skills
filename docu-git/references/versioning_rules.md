# Docu-Git 버전 관리 & 요약 추출 지침서 (Versioning & Summary Protocol)

이 지침서는 **Docu-Git** 스킬이 문서를 생성, 저장, 수정할 때 적용하는 버전 번호 부여 규칙, 파일 명명 규칙, 그리고 커밋 로그 요약 추출 가이드라인을 정의합니다.

---

## 1. 문서 버전 관리 규칙 (Document Semantic Versioning)

문서의 성숙도와 변경 규모에 따라 버전을 산정합니다.

### 1.1 버전 구성 (`vX.Y`)
- **Major Version (`X`)**:
  - `v1.0`: 문서의 최초 완전한 완성본 (최종 확정본 / 제출본 / 발행본)
  - `v2.0`: 전면 개작, 목차 구조의 전면 재구성, 메타 연구 방향의 근본적 전환 등
- **Minor Version (`Y`)**:
  - `v0.1`: 최초 아이디어 수립, 개요 작성, 뼈대 구성 (Initial Draft)
  - `v0.2 ~ v0.4`: 구체적 내용 작성, 부분 추가, 자료 보완
  - `v0.5`: 이론적 뼈대 단일화/통합, 주요 세션 완성, 중요한 관점 결합 (Major Update)
  - `v0.6 ~ v0.9`: 서론/본론/결론 보완, 문장 정교화, 참고문헌 정제
  - `v1.1`, `v1.2` ... : 확정본(v1.0) 이후의 부분 수정, 오탈자 수정, 지적사항 반영

---

## 2. 파일 명명 규칙 (Filename Conventions)

로컬 디렉토리에 저장되는 모든 문서 파일은 다음 명명 형식을 엄격히 따릅니다.

### 2.1 저장 포맷
```text
{문서 기본명}_v{버전}_{주요 변경 요약}.{확장자}
```

### 2.2 작성 규칙
1. **문서 기본명**: 띄어쓰기 허용, 문서의 핵심 주제 또는 프로젝트명 (예: `행정정책분야 성과관리 논문`)
2. **버전**: `v0.1`, `v0.5`, `v1.0` 등 소문자 `v` 접두사
3. **주요 변경 요약**: 해당 버전의 핵심 변경 사항을 괄호 또는 명료한 단어로 표현 (15자 이내 권장)
4. **확장자**: `.md`, `.hwpx`, `.docx`, `.txt` 등 사용자가 지정하거나 기본 설정된 포맷

### 2.3 저장 예시
- `성과관리논문_v0.1_기본개요 및 목차구성.md`
- `성과관리논문_v0.5_이론 단일화(젠의 역량접근법).md`
- `성과관리논문_v0.8_실증분석 결과 반영.hwpx`
- `성과관리논문_v1.0_최종확정본.md`

---

## 3. 고밀도 요약 및 핵심 추출 지침 (High-Density Summary Protocol)

Docu-Git은 원문의 길이와 관계없이 이력에 기록되는 로그를 **핵심 요지를 손실하지 않는 고밀도 요약** 형식으로 유지해야 합니다.

### 3.1 요약 원칙
1. **노이즈 제거**: 수사적 표현, 인사말, 반복 설명 제거
2. **핵심 전달**:
   - **User Input 요약**: 사용자의 핵심 Intent(의도), 요청 변경사항, 추가/삭제 지시 사항
   - **Output 산출물 요약**: 생성/수정된 핵심 결론, 변경된 논리 구조, 새로 반영된 이론/데이터
3. **길이 제한**: 입력 및 출력 각각 3~5 줄 이내 (부렛 포인트 활용)

### 3.2 요약 표준 구조
```markdown
- **요청 의도**: [사용자가 요청한 핵심 변경/생성 목적 1문장]
- **주요 수정/추가 내용**:
  - [핵심 변경점 1]
  - [핵심 변경점 2]
- **산출물 핵심 요지**: [최종 결과물의 주요 결론 또는 구조적 변화 1~2문장]
```
