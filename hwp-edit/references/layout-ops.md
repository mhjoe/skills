# 조판 작업 (Layout Operations) — `scripts/hwp_layout.py`

XML 직접 편집은 **내용과 서식**을 다루지만 **조판 결과**는 알 수 없다.
줄 수·쪽수는 한글이 다시 조판해야 정해지므로, 아래 작업은 한글 COM 경로로 한다.

| 작업 | XML 직접 편집 | COM 조판(`hwp_layout`) |
|---|:---:|:---:|
| 텍스트 읽기·검색·치환 | ✅ 빠르고 안전 | 불필요 |
| 표 셀 기입 | ✅ 좌표 + `expect_label` | 불필요 |
| 문단 추가·삭제 | ✅ `linesegarray` 규칙 준수 | 불필요 |
| 줄 수·쪽수 확인 | ❌ 불가 | ✅ `measure()`, `pages()` |
| 끝줄 1~3자 정리(자간) | ❌ 효과 확인 불가 | ✅ `fit_short_last_lines()` |
| 그림 삽입·크기 지정 | △ 바이너리 포함 번거로움 | ✅ `insert_picture()` |
| 쪽수 맞추기(분량 조정) | ❌ | ✅ |
| PDF 출력 | ❌ | ✅ `export_pdf()` |

**원칙: 내용은 XML로, 조판은 COM으로.** 한 작업 안에서 섞을 때는 XML 편집을 모두
끝낸 뒤 COM 세션을 열어 조판을 마무리한다. 반대로 하면 조판 보정이 XML 편집에
덮인다.

---

## 1. 기본 사용

```python
from hwp_layout import LayoutSession, mm

with LayoutSession("보고서.hwp") as s:       # 한글 창이 보이는 상태로 열린다
    print(s.pages())                         # 쪽수
    short = s.find_short_last_lines(3)       # 끝줄 3자 이하 문단
    result = s.fit_short_last_lines(3)       # 자간으로 한 줄 흡수
    print(result["applied"])                 # {문단번호: 적용 자간(%)}
    s.save()                                 # 같은 경로 저장(잠금 검증 포함)
    s.export_pdf()
```

### 창을 숨기지 않는 이유
`Visible = False`로 두면 조판이 계산되지 않아 커서 위치가 어긋나거나 개체 크기가
`0`으로 잡히는 판본이 있다. 계측이 목적이면 보이는 상태로 연다.

## 2. 문단 계측 — 단위에 주의

`KeyIndicator()`의 반환에서 `[3]=쪽`, `[5]=줄`, `[6]=칸`이다.
**칸은 반각 기준이라 한글 한 글자가 2칸**이다. `measure()`는 이를 그대로 돌려주므로
"끝줄 3자"는 `tail <= 6`으로 판단한다(`find_short_last_lines`가 변환해 준다).

```python
m = s.measure(32)
# {'index': 32, 'page': 2, 'lines': 2, 'tail': 3, 'multiline': True}
#  -> 2줄짜리 문단이고 마지막 줄에 약 1.5자만 남았다
```

문단 번호는 **본문 목록(list 0)의 순번**이다. 표 안의 문단은 별도 목록이라 이 번호에
포함되지 않는다.

---

## 3. 자간으로 한 줄 흡수

```python
s.set_char_shape(32, spacing=-3)     # 해당 문단만 자간 -3%
s.set_char_shape(32, ratio=97)       # 장평 97% (자간으로 부족할 때만)
```

- 문단을 블록 선택해 적용하므로 **다른 문단은 영향받지 않는다.**
- 다만 `CharShape` 실행은 선택 영역의 글자모양을 통째로 덮어쓴다. 문단 안에서 굵기·
  크기가 섞여 있으면 평탄화되므로, `uniform_char_shape(i)`로 먼저 확인한다.
  `fit_short_last_lines()`는 이 검사를 기본으로 수행하고, 혼재 문단은 건너뛴다.
- 자간은 `-3 → -5 → -7 → -10` 순으로 **필요한 만큼만** 올린다. 효과가 없으면 0으로
  되돌린다(문서 전체 밀도가 들쭉날쭉해지는 것을 막는다).

> 실무 기준: -3~-7%는 인쇄본에서 식별되지 않는다. -10%를 넘기거나 장평을 95% 아래로
> 내리면 해당 문단만 눈에 띄므로, 그 지점에서는 문장을 줄이는 편이 낫다.

## 4. 그림 삽입과 크기

```python
s.insert_picture("그림/구성도.png", width_mm=140, index=120)
```

- `InsertPicture`의 `width`/`height` 인자는 **무시되는 판본이 있다**(원본 픽셀 크기로
  들어간다). `insert_picture()`는 삽입 후 HWPML에서 `SIZE`와 `CurWidth/CurHeight`만
  고쳐 지정 폭을 맞춘다.
- **`IMAGERECT`/`IMAGECLIP`은 건드리지 않는다.** 이 값을 폭으로 바꾸면 그림이 잘린다
  (원본 좌표계 기준이라 비율이 어긋난다).
- 문서 중간에 넣으면 새 그림이 XML의 마지막에 오지 않는다. 삽입 전 `InstId` 집합을
  기억했다가 **새로 생긴 InstId**로 대상을 찾는다. 위치로 찾으면 엉뚱한 그림의 크기가
  바뀐다.
- PNG의 DPI 메타데이터는 반영되지 않는다. 크기는 항상 `width_mm`으로 지정한다.

## 5. 저장 — 조용한 실패를 막는다

```python
s.save()                       # 원본 경로
s.save("보고서_v2.hwp")        # 다른 경로
```

- **열려 있는 문서와 같은 경로로 `SaveAs` 하면 아무 오류 없이 실패한다.**
  `save()`는 현재 문서를 정리한 뒤 다시 적재해 저장한다.
- 저장 후 **수정시각을 확인**해 실제 기록 여부를 검증한다. 파일이 한글이나 동기화
  프로그램에서 열려 있으면(`WinError 32` 계열) 예외를 던진다 — 사용자에게 닫아
  달라고 요청할 것. 프로세스를 강제 종료하면 저장되지 않은 작업이 사라진다.
- `shutil.copy2`는 수정시각까지 복사하므로, 복구·백업 후 시각 비교로 성공 여부를
  판단하지 말 것.

## 6. HWPML을 직접 손볼 때

`GetTextFile("HWPML2X")` → 문자열 치환 → `SetTextFile(...)`은 문서 모델 전체에
접근하는 가장 강력한 경로지만, 그만큼 위험하다.

- **XML 파서로 재직렬화하지 말 것.** `lxml`로 파싱 후 `tostring()`으로 되쓰면
  문서가 깨질 수 있다(실제 사례: 28쪽 문서가 1453쪽이 되었다). 구조 분석에는 파서를
  읽기 전용으로 쓰고, **수정은 문자열 치환으로 최소 범위만** 한다.
- 적재 직후 `pages()`로 검증한다. `load_hwpml(xml, expect_pages=...)`는 쪽수가
  급변하면 예외를 던진다.
- 문단모양(`PARASHAPE`)·글자모양(`CHARSHAPE`)을 바꿀 때는 **기존 것을 복제해 새 Id로
  추가**하고 해당 문단만 참조를 바꾼다. 기존 Id의 속성을 고치면 그 모양을 쓰는 모든
  문단이 함께 바뀐다.

## 7. 양식(.hwp) 스타일을 물려받아 생성할 때

기관 양식 파일에서 `PARASHAPE`/`CHARSHAPE`/`STYLE` Id를 읽어, 생성하는 문단에 같은
Id를 지정하면 양식의 개조식 체계(`□ / ○ / ― / ※`)와 글꼴이 그대로 재현된다.
글머리표는 문단 스타일의 번호 매기기에서 나오므로 **본문 텍스트에 기호를 넣지 않는다.**

```python
# 양식에서 Id 추출 (읽기 전용 파싱)
tpl = LayoutSession("양식.hwp").hwpml()
# <P ParaShape="24" Style="19">  → □ 수준
# <P ParaShape="21" Style="20">  → ○ 수준
```

새 문서를 처음부터 조판하는 작업 자체는 `hwpx-report-brief` 스킬의 범위다. 이 절은
**기존 양식의 서식을 유지한 채 본문을 채워 넣어야 할 때** 참고한다.

---

## 8. 종료 — 프로세스를 남기지 않는다

`Quit()` 전에 열린 모든 문서의 수정 표시를 지우지 않으면 "저장할까요?" 대화상자가
뜨고, 자동화에는 응답할 주체가 없어 **한글 프로세스가 그대로 남는다.**
`close()`가 `XHwpDocuments.Item(i).Clear(1)`을 모두 호출한 뒤 종료한다.

작업이 끝난 뒤 확인:

```powershell
Get-Process Hwp -ErrorAction SilentlyContinue
```
