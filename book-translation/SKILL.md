# 도서 완역 스킬

로알드 달 단편 전집 48편(313,500단어) + *Fear* 선집 15편(80,563단어) 완역 작업에서 뽑아낸 절차다.
**핵심 원칙: 완역. 요약·축약·"이하 생략"은 실패다.** 이 스킬의 모든 장치는 축약을 막기 위해 존재한다.

## 0. 시작 전 3가지 확인

1. **출력 폴더**: `translations_<원전약칭>/` (프로젝트 루트). 원전이 여러 권이면 절대 한 폴더에 섞지 않는다.
2. **작업 폴더**: `scratch/` — 추출 스크립트, 챕터별 원문 `.txt`, 검증 출력. 중간 산출물은 전부 여기 남긴다.
3. **파이썬 환경**: 파이썬이 설치돼 있지 않은 환경을 전제로 한다. 스크립트는 `uv`로 실행한다.
   ```powershell
   $env:UV_CACHE_DIR="$env:LOCALAPPDATA\Temp\claude\uvcache"
   uv run --python 3.12 --with pymupdf python "scratch\스크립트.py"
   ```
   PDF 파일명에 타이포그래픽 아포스트로피(`’` U+2019)가 섞여 있는 경우가 많다. **경로를 셸 인자로 넘기지 말고 스크립트 안에서 `glob.glob("Fear*.pdf")`로 매칭**할 것.

## 1. 추출 → 분할 → 덤프

`scripts/` 의 3개를 `scratch/`로 복사해 쓴다. 원전마다 상수만 바꾼다.

```powershell
# ① 페이지 텍스트 + 내장 TOC + 메타데이터 덤프
uv run --python 3.12 --with pymupdf python "scratch\pdf_extract.py" "Fear*.pdf" "scratch\fear"
# ② TOC를 보고 scratch\fear\toc.json 을 손으로 확정한 뒤 챕터 분리
uv run --python 3.12 python "scratch\split_chapters.py" "scratch\fear"
```

- **내장 TOC(`doc.get_toc()`)를 먼저 확인한다.** 정확하면 그대로 쓴다(*Fear*가 그랬다). 부정확하면 `pdf_extract.py`가 같이 출력하는 "각 페이지 첫 줄" 목록으로 챕터 시작 페이지를 눈으로 찾는다.
- TOC의 페이지 번호는 **인쇄된 책 쪽번호가 아니라 PDF 페이지 인덱스**여야 한다. `split_chapters.py`가 각 챕터 앞머리 160자를 찍어주니 제목이 맞게 잘렸는지 반드시 육안 확인.
- 결과: `scratch/<약칭>/chapters.json` + `scratch/<약칭>/txt/NN_Title.txt`.

## 2. 번역 — 한 편 = 한 파일

**한 편씩 순서대로.** `.txt`를 Read로 읽고, 마크다운을 직접 Write한다.

> ⚠️ **가장 큰 실패 사례**: 예전 작업에서 번역문을 파이썬 문자열로 넣어 `.md`를 조립하는 스크립트(`build_story22_final_complete.py` 류 12개)를 만들었다. 결과는 18,018단어 원문에 비율 1.23의 **축약본**이었고, 또 다른 편은 0.78까지 떨어졌다. **번역문은 절대 스크립트를 거치지 않는다. Read → Write 직행.**

분량별 작성 전략:
| 원문 분량 | 방법 |
| :--- | :--- |
| ~4,000 단어 | Write 한 번에 전체 파일 |
| 4,000~10,000 | 헤더+본문 앞부분 Write → 뒤를 이어쓰기로 append (원문 **문단 경계**에서 끊는다) |
| 10,000+ | 3~4회로 나눠 append. 끊은 지점의 원문 마지막 문장을 메모해두고 다음 청크는 그 다음 문장부터 |

이어쓰기는 Bash 히어독이 가장 안전하다:
```bash
cat >> "translations_Fear/12_Afterward_나중에.md" <<'EOF'
(이어지는 번역문)
EOF
```

파일 구조·서지 블록·해설 작성법은 → `references/format.md`
번역 원칙·역주 기준·문체는 → `references/style.md`

## 3. 편마다 즉시 검증

한 편 끝낼 때마다 돌린다. 다 끝내고 몰아서 하면 이미 늦다.

```powershell
uv run --python 3.12 python "scratch\verify.py" "scratch\fear" "translations_Fear"
```

**완역 판정 지표: `ratio` = 한글 본문 글자수(공백 제외) ÷ 원문 단어수**

| 비율 | 판정 |
| :---: | :--- |
| ≥ 2.00 | ✅ 완역 |
| 1.85 ~ 2.00 | 보조 지표가 정상이면 통과, 아니면 ⚠️ 경계 |
| < 1.85 | ❌ 축약. 해당 편을 **다시 번역한다** |
| > 2.70 | ⚠️ 역주·해설이 본문 영역에 섞여 들어갔는지 확인 |

보조 지표 두 개를 함께 찍는다.
- **`sent%`** = 번역 문장 종결부호 수 ÷ 원문 문장 종결부호 수. 한국어가 문장을 더 잘게 끊으므로 **110~140%가 정상**. 85% 미만이면 문단이 통째로 빠졌다.
- **`quote%`** = 여는 인용부호 수 대조. **95~105%가 정상**. 70% 미만이면 대화를 빠뜨렸거나 지문으로 뭉개버린 것이다.

### 실측 데이터 (이 지표를 신뢰해도 되는 근거)

*Fear* 15편(전부 완역 검증됨)에 돌리면 ratio 1.99~2.44 / quote 72~107% / sent 108~162%로 **15편 전원 ✅**.
같은 스크립트를 예전 `translations/` 48편에 돌리면 **22편이 ❌**로 걸린다. 걸린 파일들의 지문은 일관된다 — ratio 1.56~1.70, **quote 1~30%, sent 22~70%**. 대화가 통째로 증발한 축약본의 전형이다.
즉 이 지표는 완역을 오탐하지 않으면서 축약을 놓치지 않는다.

## 4. 마무리 — README 색인

전편이 ✅가 된 뒤에 쓴다. 폴더 루트에 `README.md`.
- 링크는 **절대 `file:///` URL**, 공백은 `%20`:
  `[08_...md](file:///<프로젝트%20절대경로>/translations_Fear/08_....md)`
- 필수 섹션: 원전 서지 → 이 책은 어떤 책인가 → 전체 목차표(번호/원제/한국어제목/작가/페이지/단어수/링크/상태) → 작품별 한 줄 안내 → 통계 → 파일 구성 안내 → 번역 참고(역주 목록)
- 템플릿 → `references/format.md`

마지막으로 프로젝트 `CLAUDE.md`의 현황 표에 원전 한 줄을 추가한다.
