# HWPX 보고서 생성 (템플릿 스타일 상속)

한컴오피스 한글의 문서 스타일 기능을 물려받은 `.hwpx` 보고서를 만든다. 핵심은
**"내용(docx/텍스트) + 스타일 템플릿(hwpx) → 스타일이 적용된 완성 보고서(hwpx)"**.

**번들 템플릿**: `assets/template.hwpx` (지방공기업평가원 기본 보고서 양식). `--template`을 생략하면
이 파일이 기본으로 쓰인다. **이 템플릿을 한글에서 열어 스타일(글꼴·크기·색·간격·글머리표 등)을
바꿔 다시 저장하면, 다음 생성부터 바뀐 서식이 그대로 반영된다** — 스크립트가 스타일을
글머리표 문자로 매번 새로 찾아 각 스타일의 문단모양/글자모양을 그때그때 가져오기 때문이다
(ID·스타일이름·표지문구 하드코딩 없음).

## 언제 쓰나
- 사용자가 특정 HWPX 템플릿의 서식(스타일)을 그대로 새 문서에 입히고 싶을 때.
- `□ ◯ ― ※` 마커로 계층이 표현된 정부/공공 보고서 원고를 한글 양식으로 조판할 때.
- 이미 작성된 `.docx` 원고를 한글 보고서로 변환할 때(표·그림 포함).

## 입력
1. **템플릿** `*.hwpx` — 스타일과 표지·목차 틀을 담은 파일. **생략 시 번들된 `assets/template.hwpx` 사용.**
   사용자가 자기 양식을 주면 그 파일을 `--template`으로 넘기거나 `assets/template.hwpx`를 교체한다.
2. **원고** `.docx`(권장) 또는 `.txt/.md` — 아래 문단 규칙을 따르는 내용.
3. (선택) **그림 폴더** — `그림N_*.png` 형태의 이미지.

### 원고 문단 규칙
| 문단 시작 | 처리 |
|---|---|
| `Ⅰ.` `Ⅱ.` … / `참고자료` | 장 제목(템플릿 번호박스) |
| `1.` `2.` … | 절 제목 |
| `□` 로 시작 | 글머리표가 `□`인 스타일(번들 템플릿의 `□`) |
| `◯` 로 시작 | 글머리표가 `◯`인 스타일(번들 템플릿의 `ㅇ`) |
| `―` 로 시작 | 글머리표가 `-`인 스타일(번들 템플릿의 `-`) |
| `※` 로 시작 | 글머리표가 `※`인 스타일 |
| `*` 로 시작 | 글머리표가 `*`인 스타일(부연설명용) |
| `[그림 N] …` | 그림 캡션 + `그림N_*.png` 삽입 |
| `[표 N] …` | 표 캡션 (직후의 docx 표를 한글 표로 변환) |
| `출처:` / `자료:` | 작은 캡션 |
| 그 외 | 본문 |
| `graph…` / `sequenceDiagram…` (Mermaid) | 건너뜀(그림 이미지로 대체) |

## 실행
```bash
# 번들 템플릿 사용(기본)
python scripts/build_hwpx.py \
  --content "원고.docx" --figures "./그림" --out "완성.hwpx" \
  --title "표지 제목" --date "2026. 7."

# 다른 양식을 쓰려면 --template 지정
python scripts/build_hwpx.py --template "내양식.hwpx" --content "원고.docx" --out "완성.hwpx"
```
`python-docx`, `Pillow`, `lxml`(검증용)이 필요하다: `pip install python-docx pillow lxml`.

### 스타일을 바꾸고 싶을 때
1. `assets/template.hwpx`를 한글에서 연다 → [서식]-[스타일]에서 `□`/`ㅇ`/`-`/`※`/`*`/`본문` 등을 수정.
2. 저장(같은 이름 hwpx). 3. 스크립트를 다시 실행하면 바뀐 서식이 그대로 반영된다.
   - 개요 스타일은 **자동 글머리표 문자로 매칭**하므로, 스타일 **이름을 바꾸거나**(예: `ㅁ`→`□`)
     재저장으로 내부 ID가 바뀌어도 안전하다. 글머리표가 없는 스타일은 이름을 마커로 해석한다.
   - 표지 문구도 하드코딩하지 않는다. 표지에서 날짜가 아닌 첫 두 텍스트를 제목/부제로 갈아끼우므로
     템플릿의 기관명·양식명이 바뀌어도 동작한다.
   - 어떤 개요 스타일의 좌여백을 0으로 두면 글머리표가 안 보이는데(한글 특성), 스크립트가 이를
     자동 감지해 마커를 직접 삽입하고 행잉 인덴트를 준다(스타일 자체는 유지). 좌여백을 0이 아닌
     값으로 고쳐두면 스크립트는 그 스타일의 자동 글머리표를 그대로 신뢰한다.

## 동작 원리(요점)
- **스타일 자동 탐지**: 템플릿 `header.xml`의 `<hh:style …>`을 훑어 각 스타일의 문단모양/글자모양
  ID를 그때그때 가져온다. 템플릿을 다시 저장해 ID가 바뀌어도 안전.
- **마커→스타일 매칭**: 1순위는 각 개요 스타일의 *자동 글머리표(bullet) 문자*(□◯-※*), 2순위는
  스타일 이름. 원고의 `□ ■ ㅁ` / `◯ ○ ● ㅇ` / `― — – -` 같은 이형 기호는 대표 마커로 정규화한다.
- **표 셀**: 템플릿에 `표 내용` 스타일이 있으면 그 문단/글자 모양을 셀에 물려준다.
- **목차 재구성**: 목차 '제목'과 '항목 표'는 별개 문단으로 보고, 제목 문단 *다음*부터 항목 표를
  찾는다(제목 텍스트를 품은 표는 후보에서 제외). 항목은 그 표에서 *가장 넓은 칸*에 넣고, 항목
  문단모양/글자모양은 템플릿의 기존 목차 항목에서 읽는다. 항목 수에 맞춰 칸·표 높이와 문단
  레이아웃 캐시를 다시 계산하므로 목차 표가 남는 여백만큼 길어지지 않는다.
- **글머리표 렌더 결함 자동수정**: 어떤 개요 스타일의 문단모양 좌여백이 0이면 자동 글머리표가
  그려질 공간이 없어 기호가 사라진다. 이 경우 자동 감지하여 (1) 그 문단모양의 글머리표를 끄고
  (2) 행잉 인덴트를 부여하고 (3) 마커 문자를 본문에 직접 삽입한다. **문단 스타일 자체는 그대로 적용**된다.
- **레이아웃 캐시(`linesegarray`) 정리**: 기존 문단의 스타일/여백/들여쓰기를 수정할 때는 문단 내 구(舊) `<hp:linesegarray>`를 제거하여 한글 2024 로딩 시 무한 재계산 멈춤(Freeze) 현상을 방지한다.
- **표/그림**: 셀 테두리용 `borderFill`을 새로 추가하고, 이미지를 `BinData/`에 넣고
  `content.hpf` 매니페스트에 등록한다.
- **재패키징**: `mimetype`을 zip 선두 및 무압축(STORED)으로 두고, `version.xml` 및 `Preview/PrvImage.png`도 무압축(STORED) 상태로 채워 한글 2024에서 경고창 없이 정상 인식되도록 저장한다.

## 검증(생성 후 반드시)
`references/verify.py`로 well-formed 여부, 모든 스타일/문자/문단/테두리·이미지 ID 참조 해결,
mimetype 배치를 점검한다. 한글을 직접 실행할 수 없으므로 이 구조 검증이 최종 안전장치다.
```bash
python references/verify.py "완성.hwpx"
```

## 주의·한계
- 기존 문단의 스타일 및 여백/들여쓰기를 직접 개조할 경우, 구(舊) `<hp:linesegarray>` 캐시를 반드시 제거해야 한글 2024의 레이아웃 무한 루프 멈춤 현상을 막을 수 있다.
- ZIP 재패키징 시 `mimetype`뿐만 아니라 `version.xml`과 `Preview/PrvImage.png`도 반드시 무압축(`ZIP_STORED`)으로 유지해야 한글 2024의 "문서 손상/변조 경고창"을 피할 수 있다.
- 표지/목차/장-번호박스 틀은 이 템플릿 계열(지방공기업평가원 기본 보고서 양식)을 기준으로
  마커 기반 탐지한다. 완전히 다른 구조의 템플릿이면 `build_hwpx.py`의 구조 탐지부를 조정한다.
- 목차 표의 항목은 원고의 장 제목으로 통째로 재구성된다 → 템플릿에 있던 `[붙 임]`/`[참 고]` 예시 줄은
  결과물에 남지 않는다(필요하면 한글에서 직접 추가). `참고자료` 항목은 원고에 그 장이 있을 때만 붙는다.
- **목차 제목 표를 항목 표로 오인하면 목차가 세로로 폭발한다.** 「목  차」 제목을 얇은 장식 칸으로
  감싼 표가 흔한데(칸 폭 몇 mm), 그 칸에 항목을 넣으면 한 글자씩 줄바꿈되어 표가 여러 페이지로
  늘어난다. 그래서 항목을 넣을 칸은 폭이 표 전체의 50% 이상이고 최소 10000 HWPUNIT(≈35mm)일
  때만 쓰고, 미달이면 항목 삽입을 건너뛴다(로그에 이유를 남김). 구조 탐지부를 손볼 때 이 가드를
  제거하지 말 것 — 실제로 이 가드가 없어 목차가 망가진 회귀가 있었다.
- 항목 수가 줄었는데 템플릿의 `<hp:cellSz height>`/`<hp:sz height>`를 그대로 두면 그만큼 빈 공간이
  남는다. 목차처럼 내용을 갈아끼우는 표는 높이를 반드시 다시 계산한다(줄높이 = 글자 크기 ×
  줄간격 % + 문단 위/아래 간격).
- 목차의 쪽번호는 비워둔다 → 한글에서 [도구]-[차례] 자동 갱신 권장.
- 절 제목(`1.`)·출처 줄은 전용 스타일이 없으면 `바탕글`+서식으로 처리된다.
- 자세한 HWPX 내부 구조·삽질 노트는 `references/hwpx-notes.md` 참고.
