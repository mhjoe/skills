# Docu-Git 커밋 로그 템플릿 (Commit Log Template)

`DOCU_HISTORY.md` 및 프로젝트 별 이력 파일 기록 시 사용하는 규격 템플릿입니다.

---

## 1. 개별 커밋 항목 템플릿 (Commit Entry Template)

```markdown
## [Commit: doc-commit-{YYYYMMDD}-{HHMMSS}] - v{버전} ({타임스탬프})
- **파일명**: `{문서명}_v{버전}_{주요변경사항}.{ext}`
- **작성자 / 에이전트**: Docu-Git Agent (Pairing with User)
- **작업 유형**: `[NEW / UPDATE / REFACTOR / REVISION / ROLLBACK]`
- **버전 근거**: `{이력 없음 → v0.1 | 직전 v0.X + 0.1 | 사용자 지정 (v0.X, 확인 시점)}`
- **편집 기준본**: `{실제로 열어 고친 원본 파일명}` (v0.X) — 직전 최신본이 아니면 `ROLLBACK/BRANCH` 및 사용자 확인 시점 명시
- **회귀 점검**: `직전 v0.X 대비: {의도한 변경} 외 차이 없음, 이미지 n/n 동일, n쪽 {유지|변경 사유}`
- **사용 스킬 / 도구**: `{스킬명}@{버전}` ({담당 범위}), `{도구명}` ({담당 범위})

### 📥 사용자 요청 요약 (Input Summary)
> **의도**: {사용자 요청의 핵심 목적}
- **주요 지시사항**:
  - {지시사항 1}
  - {지시사항 2}

### 📤 산출물 요약 (Output Summary)
> **핵심 요지**: {산출물의 주요 결론 및 핵심 논지}
- **구조적 변화**:
  - {변화 1}
  - {변화 2}
- **추가/수정된 주요 내용**:
  - {핵심 내용 1}
  - {핵심 내용 2}

### 🔍 변경 내역 (Diff Snapshot)
- **추가/강조**: {새로 도입된 개념, 이론, 데이터}
- **제거/대체**: {삭제되거나 변경 이전 논리}
- **연관 문서/참고 자원**: `{이전버전_파일명}` -> `{현재버전_파일명}`

---
```

> **`버전 근거` 작성 규칙** (문서 커밋 전용 — 활동 기록에는 버전 근거가 없습니다)
> - 허용되는 근거는 위 세 가지뿐이며, "완성도가 높아서" 같은 추정 근거는 쓰지 않습니다.
> - `사용자 지정`은 사용자가 번호를 직접 정했거나 에이전트의 제안을 승인한 경우에만 씁니다. 상세는 [`versioning_rules.md`](versioning_rules.md) §1.

> **`편집 기준본` · `회귀 점검` 작성 규칙** ([`versioning_rules.md`](versioning_rules.md) §1.6)
> - `버전 근거`가 `직전 v0.X + 0.1`이면 `편집 기준본`도 반드시 `v0.X` 파일입니다. 둘이 어긋나면 커밋하지 않습니다.
> - "v0.X 검증 결과 반영"처럼 옛 버전이 언급되어도 그것은 수정 내용의 출처일 뿐이고, 편집은 최신본에 합니다.
> - `회귀 점검`을 쓸 수 없으면(비교를 하지 않았으면) 커밋을 확정하지 않습니다.

> **`사용 스킬 / 도구` 작성 규칙**
> - 이번 커밋에서 **실제로 사용한** 수단만 적습니다. 설치만 되어 있고 쓰지 않은 스킬은 제외합니다.
> - 스킬은 `{name}@{version}`, 스크립트·라이브러리 조합은 `{name}` 형식으로 적고 괄호에 담당 범위를 붙입니다.
> - 외부 프로그램 의존이 있으면 범위 뒤에 명시합니다. 예: `python+hwp-com` (조판·PDF, 한글 설치 필요)
> - 상세 판단 기준은 [`toolchain_tracking.md`](toolchain_tracking.md) 참조.

## 1-2. 활동 기록 템플릿 (Activity Entry Template)

문서·산출물 파일을 만들거나 고치지 않은 사전준비·자료조사·분석·검토·의사결정을 기록합니다. **버전 번호를 부여하지 않으며**, 규칙 전체는 [`activity_logging.md`](activity_logging.md)를 따릅니다.

```markdown
## [Activity: act-{YYYYMMDD}-{HHMMSS}] - {PREP | RESEARCH | ANALYSIS | REVIEW | DECISION} ({타임스탬프})
- **관련 문서**: `{doc_id}` (기준 v{그 시점의 문서 버전}) | 없음 (문서 미생성)
- **활동 유형**: `{PREP | RESEARCH | ANALYSIS | REVIEW | DECISION}`
- **상태**: `{ACTIVE | SUPERSEDED by act-… | INVALIDATED by act-…}`
- **기록 시점 / 수행 시점**: {YYYY-MM-DD HH:mm} / {YYYY-MM-DD HH:mm~HH:mm (추정 시 "(추정)")}
- **사용 스킬 / 도구**: `{스킬명}@{버전}` ({담당 범위}), `{도구명}` ({담당 범위})

### 📥 요청 요약 (Input Summary)
> **의도**: {사용자 요청의 핵심 목적}
- **주요 지시사항**:
  - {지시사항 1}

### 🔎 수행 내용 및 결과
- {수행한 조사·분석·검토의 범위(검색어·DB·데이터·모형 등)}
- **핵심 결과**: {발견·수치·결론 1~3줄. 부정적 결과("찾지 못함", "가설 기각")도 기록}
- **정정 대상** (정정·폐기 활동일 때만): {무엇이 어떻게 틀렸는지 / 영향 범위 / 수정 방법 / 영향받는 산출물과 사용 금지 표시}

### 📚 근거 자료 (Sources)
| 자료 | 검증 상태 | 비고 |
| :--- | :---: | :--- |
| {저자 (연도). 제목. 저널 — DOI/URL} | `확인됨` / `부분확인` / `미확인` | {대조하지 못한 항목, 확인 필요 사항} |

### 📁 산출·보존 위치
- {파일/폴더 경로} — `영구` | `임시` (임시이면 재생성 방법·소요 시간)
- 별도 산출 파일이 있으면: 문서 커밋 `doc-commit-…` 참조

### ➡️ 결론·미결 사항
- **결론**: {이 활동으로 정해진 것}
- **미결**: {이어받을 때 확인해야 할 것}

---
```

> **작성 규칙**
> - 자료조사는 `근거 자료` 표를 **반드시** 채웁니다. `미확인` 항목은 인용 후보에서 제외하되 삭제하지 않고 남깁니다.
> - 이전 기록을 정정·폐기하는 활동이면, 이전 기록의 `상태`를 바꾸고 헤더에 `⚠️`와 대체 기록 ID를 적습니다. 이력을 지우지 않습니다.
> - 이력이 공개 저장소에 올라갈 수 있으면 개인정보·미공개 자료를 적지 않습니다(`activity_logging.md` §8).

```markdown
| :--- | :--- | :---: | :---: | :---: |
| {프로젝트 문서명 1} | {프로젝트명} | `v{최신버전}` | {YYYY-MM-DD HH:mm} | {N}개 |
| {프로젝트 문서명 2} | {프로젝트명} | `v{최신버전}` | {YYYY-MM-DD HH:mm} | {N}개 |

> 버전은 문서 단위로 독립 관리합니다(프로젝트 단일 번호 없음). 기존 파일을 기준본으로 등록한 경우 그 사실과 파일명 미변경 여부를 이 표 아래에 적습니다.

## 🧰 작업 환경 (Toolchain)

다른 PC에서 이어서 작업할 때 아래 스킬·도구를 동일하게 갖춘 뒤 진행합니다.

| 스킬 / 도구 | 버전 | 담당 범위 | 출처 / 요건 |
| :--- | :---: | :--- | :--- |
| {스킬명} | {버전} | {이 문서에서 담당한 작업 범위} | {설치 출처 URL} |
| {도구명} | - | {담당 범위} | {외부 프로그램 등 요건} |

---

## 📌 버전 이력 타임라인 (Timeline)

- `v0.1` ({날짜}): 최초 개요 작성
- `act-{YYYYMMDD}-{HHMMSS}` ({날짜}) `RESEARCH`: 선행연구 서지 검증 (문서 버전 변화 없음)
- `v0.2` ({날짜}): 이론적 틀 보완
- `act-{YYYYMMDD}-{HHMMSS}` ({날짜}) `REVIEW`: 분석 재검토 — 이전 활동 `act-…` 를 ⚠️ INVALIDATED 처리

> 문서 커밋은 버전 번호(`vX.Y`)로, 활동 기록은 `act-` ID와 유형으로 같은 타임라인에 시간순으로 적습니다. 활동 기록은 번호를 올리지 않습니다.

**미결 사항(Open Items)**: {모든 활동 기록의 미결·`부분확인`/`미확인` 자료를 모아 한 곳에 요약. 해소되면 취소선으로 표시}

---
```
