# Docu-Git 활동 기록 지침 (Activity Logging Protocol)

이 지침서는 **문서를 생성·수정하지 않은 작업**(사전준비, 자료조사, 분석, 검토·검증, 의사결정)을 이력에 남기는 규칙을 정의합니다.

---

## 1. 왜 기록하는가

논문·보고서 같은 문서는 원고가 나오기 한참 전부터 시작됩니다. 데이터 구조를 파악하고, 문헌을 찾고, 분석을 돌리고, 결과를 다시 검토하는 과정에서 **결론과 방향이 정해집니다.** 이 과정이 이력에 없으면 다음 문제가 생깁니다.

- 문서에 적힌 결론이 **어떤 근거와 분석에서 나왔는지** 추적할 수 없다.
- 분석에서 **오류를 발견해 결과를 폐기·정정한 사실**이 남지 않아, 오류 있는 결과를 다시 쓰게 된다.
- 다른 PC·세션에서 이어받을 때 **어디까지 조사·검증했고 무엇이 미결인지** 알 수 없다.

따라서 문서 파일이 변하지 않았더라도 의미 있는 활동은 **활동 기록(Activity Entry)** 으로 남깁니다.

---

## 2. 기록 단위 구분: 문서 커밋 vs 활동 기록

| 구분 | 문서 커밋 (Document Commit) | 활동 기록 (Activity Entry) |
| :--- | :--- | :--- |
| 발생 조건 | 문서·산출물 **파일을 만들거나 고쳤을 때** | 파일 변화 없이 조사·분석·검토·결정을 했을 때 |
| ID | `doc-commit-{YYYYMMDD}-{HHMMSS}` | `act-{YYYYMMDD}-{HHMMSS}` |
| 버전 번호 | **부여** (직전 +0.1, `versioning_rules.md` §1) | **부여하지 않음** — 문서 버전을 올리지 않는다 |
| 파일명 | `{문서명}_v{버전}_{변경요약}.{ext}` | 없음 |
| 매니페스트 위치 | `documents[].history[]` | 최상위 `activities[]` |

핵심 원칙:
1. **활동 기록은 버전 번호를 소모하지 않습니다.** 번호는 문서 내용이 실제로 바뀔 때만 오릅니다(`versioning_rules.md` §1.1). 조사만 했는데 번호가 올라가면 "완성도"를 번호가 오도합니다.
2. 활동 중에 **산출 파일(코드, 결과표, 초안 등)을 새로 만들거나 고쳤다면**, 그 파일은 문서로 취급해 **문서 커밋**을 만들고, 활동 기록은 그 커밋과 서로 참조합니다. 한 번의 작업에 둘 다 있을 수 있습니다.
3. 문서가 아직 하나도 없는 프로젝트도 활동 기록은 만들 수 있습니다(`관련 문서: 없음`). 이후 첫 문서는 활동이 몇 개 있었든 **`v0.1`** 에서 시작합니다.

---

## 3. 활동 유형

| 유형 코드 | 의미 | 예 |
| :--- | :--- | :--- |
| `PREP` | 사전준비 | 원자료·코드북·조사표 구조 파악, 환경 구성, 작업 계획 수립 |
| `RESEARCH` | 자료조사 | 문헌 검색·서지 검증, 선행연구 정리, 법령·통계 출처 확인 |
| `ANALYSIS` | 분석 | 통계·데이터 분석, 시뮬레이션, 코드 실행과 결과 해석 |
| `REVIEW` | 검토·검증 | 이전 결과의 재검토, 오류 점검, 모형·근거의 타당성 평가 |
| `DECISION` | 의사결정 | 연구설계·모형·방향 선택, 보류·폐기 결정과 그 이유 |

한 번의 요청이 여러 유형에 걸치면 **유형별로 나누어** 기록하거나, 주된 유형 하나를 `활동 유형`에 쓰고 나머지를 본문에 적습니다. 나누는 기준은 "나중에 따로 찾아볼 가치가 있는가"입니다.

---

## 4. 기록 대상 판단 기준

### 4.1 기록한다
- 결론·방향·모형·인용 목록에 **영향을 준** 조사, 분석, 검토, 결정
- 이전 결과를 **폐기·정정**하게 만든 오류 발견 (반드시 기록, §6)
- 이어받는 사람이 알아야 하는 **미결 사항·확인이 필요한 항목**
- 외부 자료의 **검증 결과**(확인됨/미확인)

### 4.2 기록하지 않는다
- 단순 질의응답, 인사, 명령 실행 확인 같은 **내용이 남지 않는 대화**
- 아무 결과도 내지 못한 시도의 세부 로그(단, "시도했으나 실패해 다른 수단을 썼다"는 사실은 결과에 영향을 주면 한 줄 남긴다)
- 이미 기록된 활동의 단순 반복·재출력

### 4.3 시점 표기
- `기록 시점`: 이력에 적은 시각. `수행 시점`: 실제 작업한 시각.
- 둘이 다르면(나중에 몰아서 기록하거나 파일 저장 시각에서 추정) **둘 다 적고** 추정이면 `(추정)`을 붙입니다. 기록 시각을 수행 시각처럼 쓰지 않습니다.

---

## 5. 자료조사(`RESEARCH`) 기록 규칙

조사 결과는 **검증 상태와 함께** 남깁니다. 검증하지 않은 자료가 인용 후보로 섞이는 것을 막기 위해서입니다.

| 검증 상태 | 의미 | 인용 후보 여부 |
| :--- | :--- | :---: |
| `확인됨` | 서지(저자·연도·저널·권호/DOI)를 신뢰할 만한 출처(출판사, DOI 레지스트리, 색인 DB)로 대조함 | ✔ |
| `부분확인` | 존재는 확인했으나 일부 서지(권호·DOI·게재연도 등)를 원문으로 대조하지 못함 | 원문 대조 후 |
| `미확인` | 기억·2차 요약에만 의존, 실존 여부 미검증 | ✘ (인용하지 않음) |

- 출처는 `{저자 (연도). 제목. 저널} + {DOI 또는 URL}` 로 적습니다.
- 확인하지 못한 항목은 지우지 말고 **`미확인`으로 남겨** 같은 헛수고를 반복하지 않게 합니다.
- 등재 여부(SSCI 등)처럼 확인하지 못한 속성은 단정하지 말고 `미확인(별도 확인 필요)`으로 적습니다.
- 조사 결과 **"직접 선행연구를 찾지 못함"** 도 의미 있는 결과이므로 검색 범위(검색어·DB)와 함께 기록합니다.

---

## 6. 정정·폐기 처리 (Supersede)

이후 활동이 이전 활동·문서 커밋의 결과를 **무효로 만들거나 수정**하면, 이전 기록을 지우지 않고 상태를 표시합니다.

| 상태 | 의미 |
| :--- | :--- |
| `ACTIVE` | 유효 |
| `SUPERSEDED` | 후속 활동의 개선·대체로 더 이상 쓰지 않음 (`superseded_by` 기록) |
| `INVALIDATED` | **오류**가 발견되어 결과를 신뢰할 수 없음 (`invalidated_by`와 사유 기록) |

1. 이전 기록의 `상태`를 바꾸고 헤더에 `⚠️` 경고와 대체 기록 ID를 적습니다.
2. 후속 기록의 `정정 대상` 항목에 **무엇이 어떻게 틀렸는지**(원인, 영향 범위, 수정 방법)를 적습니다.
3. 오류 있는 산출 폴더·파일이 남아 있다면 **사용 금지 표시**를 이력에 남깁니다. 파일을 임의로 삭제하지 않고 삭제 여부는 사용자에게 묻습니다.
4. 같은 문서의 문서 커밋이 영향을 받으면 `corrected_from`이 아니라 활동 기록의 `invalidates`로 연결합니다(번호 정정은 `versioning_rules.md` §1.5 대상이 아님).

---

## 7. 산출·보존 위치와 재현성

활동 결과가 어디에 남는지 적어, 이어받을 때 재현 가능 여부를 알 수 있게 합니다.

- `영구`: 프로젝트 폴더 등 보존되는 위치의 파일
- `임시`: 세션 임시 폴더·캐시처럼 **사라질 수 있는** 중간 산출물 → 재생성 방법(실행 순서·소요 시간)을 함께 적음
- 외부 도구·API가 일부만 성공했다면(예: 호출 제한으로 일부 실패) 그 사실과 재시도 방법을 적습니다.

---

## 8. 공개 저장소 유의

이력 파일(`DOCU_HISTORY.*`)이 공개 저장소에 올라갈 수 있으면 **개인정보·미공개 연구자료**(원자료 내용, 이메일, 기관 내부 정보)를 적지 않습니다. 이 스킬 문서의 예시도 일반적인 내용만 사용합니다.

---

## 9. 활동 기록 예시 (일반 예시)

```markdown
## [Activity: act-20260315-101500] - RESEARCH (2026-03-15T10:15:00+09:00)
- **관련 문서**: `doc_001` (기준 v0.2)
- **활동 유형**: `RESEARCH`
- **상태**: `ACTIVE`
- **기록 시점 / 수행 시점**: 2026-03-15 10:15 / 2026-03-15 09:40~10:10
- **사용 스킬 / 도구**: `WebSearch` (서지 실존 검증), `docu-git@1.3.0` (이력 기록)

### 📥 요청 요약 (Input Summary)
> **의도**: 모형의 이론적 근거가 될 선행연구 조사 및 서지 검증

### 🔎 수행 내용 및 결과
- 검색 범위: "…" 등 키워드 3종, 저널 색인 DB
- **직접 선행연구는 찾지 못함.** 인접 문헌 3개 축에서 간접 도출 필요

### 📚 근거 자료 (Sources)
| 자료 | 검증 상태 | 비고 |
| :--- | :---: | :--- |
| 저자 (연도). 제목. 저널, 권(호), 쪽. DOI | 확인됨 | |
| 저자 (연도). 제목. 저널 | 부분확인 | DOI 원문 대조 필요 |

### 📁 산출·보존 위치
- 별도 파일 없음 (결과는 본 기록에만 보존)

### ➡️ 결론·미결 사항
- 가설은 인접 문헌에서 도출하고 직접 선행연구 부재를 연구 공백으로 명시
- 미결: 부분확인 항목 원문 대조
```
